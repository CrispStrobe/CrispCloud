# File Viewer engineering and design format audit

Read-only audit of `flyfish-dev/file-viewer` at **`d264009ca6efb3daed79a39d1ae63133e0f25558`**, conducted 2026-11-13. No CrispCloud application files were changed. The scope here is design, CAD/3D, EDA and drawing. GIS, ordinary image/PDF/Typst/OFD, office and media paths are assigned to other reviewers.

The user's expanded policy admits Apache, MIT, BSD and similar permissive software, plus MPL. “Candidate” below means the identified execution path fits those families, with its notices and any MPL source duties; it is not a claim that the complete npm package, asset pack or preset has the same license. OFL fonts, CC0 profiles, EPL components and custom asset grants are stated separately. Exact installed/distributed artifact inventories still belong in the implementation checkpoint.

## Material conclusions

1. **PSD/PSB, native AI, InDesign exchange, palettes/resources, IDML and optional IFC offer useful new candidates.** IDML explicitly elects MPL-2.0 from `MPL-2.0 OR LicenseRef-PMEL`; IFC uses MPL-2.0 Web-IFC with MIT That Open libraries. Neither requires electing an unavailable proprietary grant.
2. **EPS/PostScript's Stet software is Apache-2.0 OR MIT with permissive native dependencies.** Its current fonts are 35 URW Base35 fonts with a documented OFL-1.1 election, and its embedded CMYK profile is CC0. It is not using a Ghostscript profile. This changes the prior Apache-only assessment materially, but the font terms remain separate.
3. **DXF/DWG/DWF/DWFX on the bundled CAD route remain outside this policy.** The runtime is AGPL; DWG also uses GPL LibreDWG. STEP/IGES/BREP use LGPL OCCT and `occt-import-js`, which MPL permission does not automatically approve.
4. **Default draw.io SVG and rough.js Excalidraw are separable candidates. Official draw.io assets are not simply Apache.** The shipped icon/stencil/shape licenses prohibit use as assets in Atlassian products/marketplace products without permission. Its MathJax fonts add OFL, GUST/LPPL and specific custom font grants.
5. **Mermaid is not an all-MIT closure at this pin.** Mermaid 12.2.0 includes `elkjs` 0.9.3 under EPL-2.0, with retained underlying Java notices including EPL-1.0. The user's explicit MPL allowance does not itself authorize EPL. BPMN separately has the custom bpmn.io visible-watermark condition.
6. **Do not import complete packages merely because one format route is acceptable.** `renderer-3d` depends on the LGPL geometry engine; `renderer-drawing` depends on the Mermaid capability. A permitted mesh or draw.io route needs a deliberately bounded build/extraction that omits the disallowed runtime chunks and assets.

### PostScript / IDML asset detail

- **Stet source:** `58c7066817f7939789c6f030515c02e94fb0353b`. The 35 font files match `ArtifexSoftware/urw-base35-fonts` commit `3c0ba3b5687632dfc66526544a4e811fe0ec0cd9`. The retained notice records the historic triple-license declaration and the OFL election. This is not an inference that all Artifex assets are permissive. Carlito, Tinos, Cousine and Noto Sans Symbols 2 notice URLs are retained for compatibility, but those fonts are **no longer embedded** in this engine. [Font notice][urw]
- **CMYK:** `CGATS001Compat-v2-micro.icc`, Compact ICC Profiles commit `1fabe4a41bef9bac6e8300748177f783773571cb`, **CC0**, 8,464 bytes, SHA-256 `73e1ba37d2bad5bab2a964f40a9eed96209666efc067c3322626214bbef234a0`. The checked-in source pin identifies both profile and license. [Profile/build][ps]
- **Introspect source book:** 175 normal WASM source packages; selected licenses are 112 Apache, 36 MIT, 16 MPL, 2 BSD-2-Clause, 4 BSD-3-Clause, 2 Zlib, 2 Unicode and 1 Apache-plus-Unicode. It also retains separate Adobe/Foxit asset grants, full standard-library notices and embedded-pattern grants. The Adobe CMap and Foxit-named assets use standard BSD-3-Clause texts; the latter credits PDFium Authors and includes Google nonendorsement. These inventories conservatively cover bundled or test assets, without claiming every asset survives linking. The source restoration uses core commit `8eb9e21febaffbf5bb15e5158bb83896141682b2` plus migrated publish source `116e5df5dab8bd5b7677c1155a79cb0ed3048a4a`. The book states `releaseApproval: false` and does not assert a bit-for-bit WASM rebuild; it is strong provenance evidence, not a legal sign-off. [Book][idml-book], [explanation][design-notices]

## Documentation and provenance discrepancies to carry into the import review

- `design/package.json` and `pnpm-lock.yaml` install **ag-psd31.0.3**, while `design/THIRD_PARTY_NOTICES.md` and a generated Photoshop-resource catalog label still say **31.0.2**. The retained MIT grant is useful, but the exact 31.0.3 package notice/artifact should be reconciled before redistribution. No fixtures from upstream ag-psd are approved by its code MIT grant.
- `drawing/package.json` and lock install **bpmn-js18.31.1 / diagram-js15.28.1**, while the retained drawing notice says **18.28.0 / 15.26.0**. I independently fetched bpmn-js18.31.1's upstream license at commit `e7b7435ed60f662b3d80caaefe5dccba5d3a4c75`; its watermark condition is still present. Correct the labels and preserve the exact current grant if this path is later approved.
- Geometry README's “IFC not wired” applies to the ordinary geometry-engine route, not the newer optional `/ifc` entry. Use IFC.md and the optional asset copier as the capability authority.
- The lock resolves Three.js **0.186.1** although its manifest range starts at0.186.0. I checked the MIT project grant at r186 commit `9b4a2ac29c63ccb43fd51c5661f2f873ac2c39b8`; I did not reconstruct every0.186.1 addon/decoder artifact in this read-only survey. The import checkpoint must retain its exact distributed notices, especially for compressed mesh codecs.
- Broad asset ledgers deliberately say `releaseApproval: false` / material-identity-only. Preserve this distinction when using their hashes and licenses; they are not an automatic approval of every complete package.
