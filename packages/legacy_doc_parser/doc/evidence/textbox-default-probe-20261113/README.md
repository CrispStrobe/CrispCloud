# Textbox default width: bounded follow-up

No textbox width or frame-geometry change was accepted from these probes. The
six Word14 textboxes still have unresolved shape effects, so the current writer
preserves their absent source widths and leaves them outside the verified
explicit-border frame transformation. The measurements narrow the next
investigation without treating one output adjustment as a complete source
mapping.

## Reproduced current behavior

The clean parser at `91baa8f1e53363190b28ca9af9905f11799b2d00` again renders the
unchanged `word14-margin-origin.doc` with **0.75-point** maximum corresponding
word displacement. Its words, layout text, page count and page dimensions match.
The initial RGB raster still differs.

Through three repeat cycles, each parser conversion matches its own regenerated
binary input exactly in word positions, layout text and RGB raster. The native
DOCX-to-DOC bridge adds 0.05 points per cycle; cumulative differences from the
first parser import are 0.05, 0.10 and 0.15 points. This reproduces the earlier
bridge attribution after the explicit-border correction was integrated.

The runtime identity here predates the later line-dash evidence guard. The
guard has its own portable checks and does not change Word14 stroke defaults.
This receipt makes no claim about a later combined runtime's native acceptance.

## Output-only counterfactuals

The probe starts from the retained wrap-only DOCX generated by clean runtime
`ab575729720f0b6f7f2316e8613e7780be950356`. It changes only each VML textbox's
stroke width and, where named below, its rectangle. All other package parts are
copied unchanged. Each variant is rendered against the original binary source
using the same installed LibreOffice/Poppler environment.

| Variant | Explicit width | Rectangle adjustment | Maximum word displacement |
| --- | --- | --- | ---: |
| Unchanged retained output | Absent | None | 0.75 pt |
| Width only | 0.75 pt | None | 0.40 pt |
| Width and outer frame | 0.75 pt | Left/top minus 0.35 pt; width/height plus 0.70 pt | 0.20 pt |
| Width and opposite frame | 0.75 pt | Left/top plus 0.35 pt; width/height minus 0.70 pt | 0.70 pt |

All four preserve the source word sequence and layout text. None is RGB-exact.
The 0.20-point result is within the runner's existing 0.25-point word-position
tolerance; it does not establish exact geometry or authorize the transformation
for unresolved effects. These counterfactuals were not repeat-cycle or schema
acceptance runs and were never merged into the runtime.

[MS-ODRAW lineWidth](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-odraw/fb88b56e-2c2d-41c2-a0c8-98129e913b89)
defines the 9,525-EMU default. The [VML implementation notes](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/d019f23f-5977-43d8-b463-99ba8f6784eb)
describe the difference between the standard and Office stroke-weight defaults.
The independent [binary importer](https://github.com/LibreOffice/core/blob/9a3be2502bf7762400fd0b655b6e42714cf2bb36/sw/source/filter/ww8/ww8graf.cxx)
converts a simple textbox's outside half-border to frame coordinates. These
sources explain the counterfactuals; they do not resolve Word14's other effects.
The earlier [width-only retraction](../../textbox-stroke-defaults.md) and all its
failed repeat measurements remain unchanged.

## Rejected synthetic controls

Six additional hand-assembled body/header boundary fixtures tested omitted,
explicit 0.75-point and disabled borders. Omitted and explicit width source
renders agreed, but their native source and parser renders differed in text and
page dimensions. These fixtures were built for parser-boundary assertions and
are not suitable native layout controls. Their matching width pair therefore
does not certify textbox default placement. Inputs, rendered outputs, logs,
generator and the exact temporary fixture variant are retained alongside this
failure. No test fixture or source golden was rewritten.

## Retained artifacts and verification

`diagnostics.tar.xz` contains the complete new Word14 baseline run and three
repeats, output-only probe inputs and outputs, rejected synthetic controls,
PDFs, extracted text/word bounds, and lossless compressed RGB page rasters.
The exact source DOC, probe code, runtime build/source receipt and renderer/font
identities are included. Native temporary profiles, compiled executables and
downloaded third-party source code are excluded.

`manifest.json` binds every regular archive member by size and SHA-256, and also
binds `summary.json`. The verifier checks complete member coverage, every
compressed and raw raster hash, the summarized comparisons and unchanged source
identity without extracting the archive:

```sh
python3 doc/evidence/textbox-default-probe-20261113/verify.py
```

The archived `probe.py` reproduces the four output-only variants from the already
retained wrap-only artifact; use a new output directory when rerunning it. The native
baseline is reproducible at its recorded clean commit with `tool/fidelity/run.py
--case word14-margin-origin --roundtrip-cycles 3 --raster-storage gzip` and the
recorded toolchain. New measurements must retain their own source identities.
