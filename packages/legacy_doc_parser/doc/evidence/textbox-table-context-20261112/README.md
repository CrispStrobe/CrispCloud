# Rejected textbox table-depth reset

The reset proposed at `233a76e` passed portable model tests and the independent
schema validator, but a native source control disproved its layout assumption.
It is retracted in the following runtime checkpoint. Its evidence is retained
so a later source comparison does not mistake that checkpoint for a fidelity fix.

The literal OOXML authoring script uses the same textbox content and 240-twip
cell margin in a paragraph anchor and a table-cell anchor. Installed LibreOffice
converts each source to DOC; exactly those binary bytes are supplied to the
baseline converter (`fdeb82c`) and the reset candidate. No expected DOCX is
generated by the parser. The baseline compiler/source/executable receipt and
candidate source inventory are included in the archive.

| Native DOC source | Parsed boundary origin | Margin | Baseline DOCX indent | Candidate/native DOCX indent | Source/baseline cell offset | Candidate/native DOCX offset |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Paragraph anchor | 480 twips | 240 twips | 720 twips | 720 twips | 36 pt | 36 pt |
| Table-cell anchor | 720 twips | 240 twips | 720 twips | 960 twips | 48 pt | 60 pt |

Offsets are CELL's horizontal position relative to BOX in the same textbox.
All absolute marker boxes, native PDFs, exact DOC/DOCX inputs and outputs,
authoring code, converter output and source hashes are retained. The parser's
whole textbox is also translated by 0.35 pt versus the native DOC; this is a
separate remaining placement difference. No whole-page or RGB equality follows
from the relative table-position result.

The native DOC-to-DOCX exporter itself produces the same 12 pt error in the
table-anchor case. Matching its `tblInd` value is therefore not an independent
fidelity certificate. The unchanged baseline retains the source's relative
geometry; restoring it does not depend on selecting a native-exported value.

The two header controls remain diagnostics: one hits the known unresolved
header textbox chain, and the table-only ending additionally exposes the header
range boundary restriction. They are not counted as passing parser cases.
The earlier independently assembled binary control is also retained: this
native renderer omits its textbox, so it serves only parser/schema checks.
