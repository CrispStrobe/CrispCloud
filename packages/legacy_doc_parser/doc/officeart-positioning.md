# Word OfficeArt positioning

The DOC reader retains explicit FOPT `posh`, `posrelh`, `posv`, and `posrelv`
properties separately from the older SPA rectangle and origins. A supported
explicit property takes precedence on its own axis. An absent or unsupported
property leaves that axis on its original SPA fallback. No page margin is
added to or subtracted from the signed source offsets.

The supported Word-specific origin values are:

| Raw FOPT value | Horizontal origin | Vertical origin |
| --- | --- | --- |
| 0 | Margin | Margin |
| 1 | Page | Page |
| 2 | Column/text | Paragraph/text |
| 3 | Character | Line |

Absolute positions retain their signed offsets. The five nonzero alignment
modes remain native left/top, center, right/bottom, inside, and outside.
VML textboxes and shapes, and DrawingML images use the same resolved origins.
VML `w10:wrap` accepts only margin/page/text, so character/line origins appear
in the VML style without an invalid legacy wrap-anchor attribute.

## Why this differs from the generic specification table

The generic [MS-ODRAW posrelh](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-odraw/e6d6737b-189d-4ce9-ada1-3fff4c4e7512)
and [posrelv](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-odraw/e8351af1-c736-4e34-8bf1-1a7497b6cd41)
pages number margin/page/text/character-or-line from one. This is inconsistent
with the Word-specific producer/consumer evidence below. The implementation
does not silently apply that generic numbering to Word DOC files.

Microsoft's archived [RTF 1.9.1 specification](https://officeprotocoldoc.z19.web.core.windows.net/files/Archive_References/%5BMSFT-RTF%5D.pdf),
printed pages 162–166, describes Word97–2007 shapes. Pages 163–164 explain the
new shape properties and their precedence over older anchor keywords; page 166
lists the zero-based values above. RTF alone would not prove binary encoding.
The retained independent binary samples supply that additional evidence:

- LibreOffice QA `tdf101826_xattrTextBoxFill.doc` identifies Microsoft Office
  Word 14.0 in its OLE property sets. Its textbox 1028 has an explicit binary
  `posrelh=0`, SPA `bx=0`, and horizontal offset 5460 twips. The exact FOPT bytes
  are at offset 16168 in `1Table`; the matching SPA starts at 28138.
- LibreOffice QA `tdf124601.doc` identifies Microsoft Office Word 16.0.
  Shapes 1026 and 1027 have explicit `posrelv=1`, SPA `by=1`, and different
  nonzero vertical offsets 45 and 594 twips. The exact FOPT offsets are 6233
  and 10600. This file also exercises the complete parser and DrawingML writer.
- [LibreOffice's Word binary importer](https://github.com/LibreOffice/core/blob/9a3be2502bf7762400fd0b655b6e42714cf2bb36/sw/source/filter/ww8/ww8graf.cxx)
  (`ProcessEscherAlign`) independently uses the same zero-based origins,
  giving explicitly stored origins precedence over SPA on each axis.

The Word application metadata is provenance evidence, not a signature or a
record of a Word execution in this environment. Source URLs, Git blob hashes,
SHA256 hashes, raw observations, and attribution are in
`doc/evidence/officeart-position-sources.json`. The samples were obtained from
the public LibreOffice QA repository and were not generated by this converter.
The Word 14 sample initially exposed a separate textbox-range rejection. The
explicitly diagnosed recovery below now imports its six real textboxes; this
does not certify arbitrary effects or complete rendering fidelity.

## Boundaries and validation

Values outside the supported origin range 0–3 or alignment range 0–5 remain
raw model values and unsupported-property evidence. Complex values cannot
be treated as scalar enums. Unsupported origins select no new relationship;
native output retains the independently validated SPA fallback. No speculative
mapping is made for the additional RTF margin-edge values 4–7.

Literal binary tests cover all four origins, partial-axis overrides, alignment
modes, negative and positive offsets, unknown values, and complex records.
Both retained linked-textbox fixtures are checked independently. The original
eight-marker file remains `linked-textboxes.doc`; the recovered 24-marker
fixture remains `linked-textboxes-extended.doc`.

`tool/fidelity/textbox_reflow.py` measures resize reflow separately from absolute
placement. Its relative-reflow check may disclose one common translation;
the placement check keeps the original authored frame bounds. Fixing the
origin must pass the latter without subtracting a measured 72-point drift.
General exact pagination, arbitrary effects, and all anchor contexts remain
separate fidelity goals.

## Bounded recovery of a global textbox spare sentinel

[MS-DOC PlcftxbxTxt](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/9f17f89a-64d6-4546-a811-e62e1d238102)
ignores the last spare range's text and does not require a CR in that range.
The Word 14 fixture has a 119-character textbox story whose six real boxes
end at CP118. Its ignored final range ends at CP135: the exact length of the
whole document plus one (15 body +119 textbox +1). No bytes at that dummy
endpoint are read.

The recovery accepts that endpoint only for a main-document textbox story,
only when every real CP is bounded and strictly ordered, and only when the
last real endpoint is exactly one character before the textbox story ends.
All real box CRs, shape references and chain relationships still validate.
Other out-of-range or unsorted dummy endpoints reject the input. The warning
`recoveredGlobalTextboxSentinel` and the conversion's partial-formatting
limitation expose the recovery. Tests cover the original source, a conforming
local endpoint, altered global endpoints, invalid real endpoints, and duplicate
real ranges. Header textboxes retain their existing stricter endpoint rule.

## Native positioning receipt

`doc/evidence/textbox-position-native-49959f9.json` records the clean checkpoint
measurement. The compact fixture passes absolute placement and resize reflow
separately, with zero word-position drift and no translation. Its RGB raster
still differs in five pixels by one channel level per page; strict raster
equality therefore remains false. Both extended authored and retained-native
fixtures are RGB-exact on the recorded renderer. These outcomes are specific
to that renderer and font inventory, not a claim of general exact pagination.
